# Marketing Wizard: DPA AD's company dashboard

Internal operating system for **DPA AD** (dpa.ad): a pre-launch Saudi SaaS that turns ecommerce catalogs into designed image and video ads for Meta, Snap, TikTok and Google. Arabic-first, Salla/Zid stores first, goal $100M ARR. Live at **https://wizard.dpa.ad**. This repo is the dashboard, not the DPA AD product itself.

Principle across every module: **AI does every step it can; people do only what must be human** (approvals, live calls, contracts, anything the AI flags). AI drafts are reviewed before anything reaches a customer.

## Run, test, deploy

```bash
cd web && npm install
DASHBOARD_PASSWORD=test-pass PORT=3000 node server.js   # open http://localhost:3000, leave email empty, password test-pass
npm test                                                 # node:test, web/test/app.test.js, all must pass
npm run sop:md                                           # regenerate docs/SOP.md after editing lib/sop.js
```

- **Deploy:** push to `main` on GitHub `vistarbpo/MarktingWizard`. Hostinger auto-deploys `main` (root dir `web`, entry `server.js`, Node 22, Express). Check a deploy by fetching `https://wizard.dpa.ad/app.css` for a new CSS rule, plus `/healthz`. Other pages need a login.
- **Env vars** live in hPanel (Websites → wizard.dpa.ad → Node.js → Environment variables), never in git: `DASHBOARD_PASSWORD`, `ANTHROPIC_API_KEY`, optional `MWIZ_MODEL`, `DATA_DIR`, and the Store CRM channels (`SMTP_*`, `MAIL_FROM`, `MAIL_REPLY_TO`, `IMAP_*`, `WA_TOKEN`, `WA_PHONE_ID`, `WA_VERIFY_TOKEN`, `WA_APP_SECRET`, `PUBLIC_URL`, `COMPANY_ADDRESS`, `INBOUND_SECRET`) and Creative Studio publishing (`TOKEN_KEY`, `META_APP_ID`, `META_APP_SECRET`, `META_VERIFY_TOKEN`, optional `META_GRAPH_VERSION`, `LINKEDIN_CLIENT_ID`, `LINKEDIN_CLIENT_SECRET`, optional `LINKEDIN_ORG_ID` and `LINKEDIN_VERSION`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `YOUTUBE_AUDITED`, `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET`, `TIKTOK_AUDITED`), Paid Ads (Meta reuses `META_APP_ID`/`META_APP_SECRET`; `SNAP_CLIENT_ID`, `SNAP_CLIENT_SECRET`, `TIKTOK_ADS_APP_ID`, `TIKTOK_ADS_SECRET`, optional `ADS_GOOGLE=1` with `GOOGLE_ADS_DEVELOPER_TOKEN` and `GOOGLE_ADS_LOGIN_CUSTOMER_ID`, `ADS_LEAD_SECRET`; review flags `META_ADS_REVIEWED`, `SNAP_ADS_APPROVED`, `TIKTOK_ADS_APPROVED`, `GOOGLE_ADS_BASIC_ACCESS`), backups (`BACKUP_KEY`, required to encrypt and to send off-site; optional `BACKUP_S3_ENDPOINT`, `BACKUP_S3_BUCKET`, `BACKUP_S3_KEY`, `BACKUP_S3_SECRET`, `BACKUP_S3_REGION`, `BACKUP_S3_PREFIX`, `BACKUP_S3_PATH_STYLE`, `BACKUP_EMAIL_TO`, `BACKUP_EMAIL_MAX_MB`, `BACKUP_MEDIA`, `BACKUP_MEDIA_MAX_MB`, `BACKUP_LEGAL_MAX_MB`) and Billing (`MOYASAR_SECRET_KEY`, `MOYASAR_WEBHOOK_SECRET`, `BILLING_USAGE_TOKEN`, optional `ZATCA_ENV`, `ZATCA_CSID`, `ZATCA_CSID_SECRET`). Set `TOKEN_KEY` before connecting accounts: without it the token key comes from `DASHBOARD_PASSWORD`, and rotating the password means reconnecting every account. The full list is commented at the top of `web/server.js`.
- **Data** is not in git: `DATA_DIR` (default `~/marketing-wizard-data`) holds `db.json` (everything except the CRM, including employees, punches, leave and payroll runs) and `crm.json` (stores, campaigns, messages; batched writes, flushed on SIGTERM), plus `media/` (Creative Studio uploads and renders, served publicly at `/media/<random>.<ext>`) and `legal/` (Legal & documents files, private, served only through authenticated routes). **Backups** run nightly at 02:00 Riyadh into `DATA_DIR/backups/` (encrypted with `BACKUP_KEY`, last 14 nightly + 8 weekly + 10 manual, optional S3/email copy); restore with `web/scripts/restore-backup.js`, steps in `docs/security-compliance.md`.
- Without `ANTHROPIC_API_KEY` the app runs a demo provider (sidebar shows "Demo mode").
- To stop a local server: `for p in $(pgrep -f "^node server.js"); do kill $p; done`. Don't use `pkill -f "node server.js"`: it kills the shell running it.

## Code map

Node 22 + Express, plain JS ES modules, no build step, no frontend framework.

- `web/server.js`: entry. Creates `Store`, provider (Claude via `@anthropic-ai/sdk`, or demo) and the app, and starts the CRM, Creative Studio, billing, Customer Success, Market intel and Goals & review (OKR) schedulers (Meetings has no scheduler).
- `web/lib/app.js`: `createApp({ store, provider, password, crm, outreachOptions })` holds all routes. Order:
  1. login
  2. public routes (support chat, CRM unsubscribe and webhooks, `/hooks/moyasar`, `/hooks/billing/usage`, survey answers `/s/:token`, the public help site `/help`)
  3. auth middleware (session, per-module permission, audit log)
  4. API routes

  Streaming AI responses end with `\n\n[[MWIZ_SAVED]]id` or `[[MWIZ_ERROR]]msg`.

## Rules this codebase follows

- Never invent numbers, results, customers or quotes in AI prompts or UI; use placeholders like `[ADD]`.
- Arabic-first customer copy (Saudi dialect), `dir="auto"` on user text, `esc()` everything rendered.
- Outreach safety:
  - unsubscribe link and header on every email; "stop" / "إلغاء" honoured
  - sequences stop when a store replies
  - sends only 09:00–21:00 Riyadh time, not Friday
  - WhatsApp only to opted-in numbers, with approved templates outside the 24h window
  - sample stores are never sent for real
  - store pages are fetched only by `products.js` (`safeGet`): public addresses only, 8 s, ~2 MB, 2 at a time
  - Test mode by default
- Every feature gets a test in `web/test/app.test.js`, and the whole suite must pass before pushing.
- Page scripts share one global scope: never reuse a top-level name from another `public/*.js` file (a test enforces this).
- Check UI changes in a browser (Playwright is available) at desktop and phone width, with no horizontal scroll on phones.
